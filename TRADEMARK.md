## What you may do without asking

- Use the unmodified `koment` binaries, packages and source distributed from
  this repository or its official release channels.
- Refer to the project by name in plain prose when describing what the code
  does ("we use koment to track rationale"), including in articles, talks and
  documentation about the unmodified tool.
- Link to <https://github.com/koment-dev/koment> and to the official documentation
  site.

## What you may not do without permission

- Use the `koment` name, wordmark or logo as the name of a derived or forked
  product. Forks must rename themselves and use their own marks.
- Distribute a modified build, container image, Helm chart or extension under
  a name or logo that is likely to confuse a reasonable person about whether
  it is the official project. This includes the official publisher namespaces
  on package managers and editor marketplaces.
- Use the marks in marketing, advertising or merchandise for any product that
  is not the unmodified official project.
- Register or claim a domain, social-media handle, marketplace publisher
  account, OCI namespace, package identifier or MCP registry identifier that
  begins with `koment` or a substantially similar name for a forked or
  competing product.

## Why the marks are not part of the AGPL grant

The AGPL governs copying, modification and distribution of source code. It is
not designed to govern brand identity. Letting any fork call itself "koment"
would make it impossible to tell official releases from third-party builds,
and would undermine the trust the project is built on. The marks are held
separately so that the code can stay maximally open while the identity stays
trustworthy.
